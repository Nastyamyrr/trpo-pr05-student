## Краткое описание результата

PHP-приложение с объектной моделью каталога товаров:

- `Product` и `Category` — модели предметной области с конструкторами и валидацией
- `CatalogService` — загрузка dataset, фильтрация по категории, расчёт средней цены и суммы
- `public/index.php` — представление (HTML-карточки + форма фильтра)

Данные берутся из `data/products.json` и `data/categories.json`. HTML не смешивается с моделями.

## Схема ответственности

```
Product / Category  →  CatalogService  →  index.php
     (модели)              (сервис)         (представление)
```

| Элемент          | Ответственность                                      |
|------------------|------------------------------------------------------|
| Product          | Состояние одного товара, предметные методы           |
| Category         | Состояние одной категории                            |
| CatalogService   | Чтение JSON → объекты, фильтры, агрегаты             |
| index.php        | HTTP-запрос, вызов сервиса, экранированный HTML      |

## Требования к окружению

- PHP 8.0+ (используются typed properties, constructor property promotion, `declare(strict_types=1)`)
- Веб-сервер с поддержкой PHP **или** встроенный сервер PHP

## Запуск

### Вариант 1 — встроенный сервер PHP (рекомендуется для проверки)

```bash
cd public
php -S localhost:8080
```

Откройте в браузере: http://localhost:8080

### Вариант 2 — Apache / Nginx

DocumentRoot должен указывать на папку `public/`.

## Что реализовано по пунктам задания

1. Структура каталогов `public`, `src/Model`, `src/Service`, `data` + dataset.
2. Свойства взяты из `class_requirements.csv` + поле `active` из JSON (имеет смысл для фильтра).
3. Класс `Product` — обязательные значения только через `__construct`, типизация.
4. Предметные методы Product: `formattedPrice()`, `statusLabel()`, `belongsToCategory()`, `belongsToAnyCategory()` (+ геттеры).
5. Класс `Category`, связь Product → Category по `categoryId`.
6. `CatalogService` читает оба JSON и создаёт массив объектов.
7. HTML только в `index.php`, модели чистые.
8. Фильтр по категории + средняя цена / сумма / количество.
9. HTML-карточки, `htmlspecialchars` (функция `e()`).
10. Валидация в конструкторах → `InvalidArgumentException` (демо: `docs/invalid-constructor-demo.php`).
11. Форма фильтра (GET), логика фильтра в сервисе, не в Product.
12. `require_once` для классов. При росте проекта неудобно: появляются циклические зависимости, забытые подключения, порядок загрузки. Решение — Composer + PSR-4 autoload.
13. Все 12 строк `products.json` обрабатываются (включая `active: false`).
14. Схема в README (см. выше).
15. Несколько осмысленных коммитов (см. историю Git).

## Проверка ошибочного конструктора

```bash
php docs/invalid-constructor-demo.php
```

Ожидается перехват `InvalidArgumentException` при отрицательной цене / пустом имени / невалидном id.

## Сценарий проверки после клонирования

1. `git clone <url> && cd trpo-pr05`
2. `cd public && php -S localhost:8080`
3. Открыть http://localhost:8080 — видны 12 товаров, статистика, фильтр.
4. Выбрать категорию «Оборудование» → остаются товары с `category_id = 2`.
5. Включить «Только активные» → скрываются id 5 и 10.
6. Сбросить фильтр → снова полный список.

## Контрольные ответы (кратко)

1. **Входные данные:** `data/products.json`, `data/categories.json`.
2. **Преобразование в интерфейс:** `index.php` (цикл по объектам Product → HTML-карточки).
3. **Ошибочное состояние:** пустой результат фильтра; невалидный конструктор (demo); отсутствие/битый JSON → RuntimeException.
4. **При росте:** autoload (Composer), разделение Controller/View, репозиторий вместо прямого чтения JSON, DI.
5. **После клона:** `php -S` из `public/` по README.
6. **PHP vs JS:** PHP выполняется на сервере до отдачи HTML; JS — в браузере после загрузки страницы.
7. **Конструктор:** гарантирует валидное начальное состояние объекта (инвариант).
